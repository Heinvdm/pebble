## Pebble script S7: the phone's isolated process (23 October 2026), checked on the emulator
From `plans/pebble-script.md` S7 and "The five layers, as built", layer 2. `android/README.md` "Pebble script on the phone" and `brain/README.md` "Pebble script" have the details. Nothing has run on the Pixel 6 Pro.
- **The first hour: Chaquopy does not start in an isolated process.** A throwaway service with `android:isolatedProcess="true"` on Pebble_API35 (uid 99003, `Process.isIsolated()` true): `new AndroidPlatform(context)` threw "SharedPreferences cannot be accessed if UserManager is not available. (e.g. from inside an isolated process)", so `Python.start` never ran and `Python.getInstance()` then refused ("Cannot use GenericPlatform on Android"). The app's files folder, where Chaquopy unpacks Python, could not be listed. `NotificationManager` was null there, which would have crashed `PebbleApp.onCreate` (it now returns early in an isolated process). Unbinding the service, Android killed its process within 7 ms ("isolated not needed"). The throwaway service and its test were removed; the finding is in NOTES.md.
- **So the evaluator is ported to Kotlin** (`android/app/src/main/java/nz/pebble/robot/script/`): `Machine.kt` (the evaluator, with the pure and the pausing paths of `evaluate.py`, pausing at each ability call through a Kotlin `sequence`), `Program.kt` (the JSON program, the purity marks, the limits and the ability signatures), `Values.kt` (Python's numbers, text, comparisons, `repr`, `round`, slices and the float formatting), `Json.kt` (its own reader and writer, so the JVM and the phone parse the same way and dicts keep their order) and `ScriptHost.kt` (the JSON lines of `pebble.script.host`: `load`, `run`, `reply`, `stop`, `drop`, `ping`, `quit`). It runs only the JSON program, holds only plain values and keeps every limit of the Python one.
- **The vectors:** all 139 replay identically in Kotlin: `ScriptVectorsTest` on the PC's JVM (twice in a row, and a vector with a wrong answer is caught), `ScriptServiceTest` on the emulator's runtime and again through the isolated service. They are copied from `brain/pebble/script/vectors/` by the build (`syncVectors`, `syncVectorAssets`), never by hand. A one-off replay of 141 more programs written by the Python evaluator (the red-team programs, the 15 starters, about 80 edge cases) also agreed on every call and outcome; that check was not kept in the repo.
- **The isolated service:** `ScriptService` (`android:isolatedProcess="true"`, process `:script`, no permissions) runs the host on a thread with a 16 MB stack. The brain's `Phone` engine (`brain/pebble/script/host.py`, beside `Local` and `Process`) calls `scriptOpen`, `scriptAsk` and `scriptClose` on `Bridge`; `ScriptLink` in `:brain` binds one isolated instance per running program (`bindIsolatedService`), refuses one whose `ping` doesn't say it is isolated, and counts 3 s without an answer (10 s for a load) as a crash, unbinding so Android kills the process. The service also ends itself after 5 s of computing on one message, or when its heap stays over 64 MB after a collection (the memory ceiling; the evaluator's own 256 KB of values is the first one), saying why first when it can. `Scripts.make_engine` picks `Phone` on Android (`script_engine` `"process"`, or `"phone"` anywhere); `"local"` stays local, and the dream still runs in the brain's own process.
- **Instrumented tests on the emulator** (`app/src/androidTest/.../script/ScriptServiceTest.kt`, the first instrumented tests in the app; `androidx.test` runner 1.6.2 and ext-junit 1.2.1 added for them), 8 of 8 pass: the vectors on the runtime and through the service; its own pid and an isolated uid (99053, 99077); the sandbox (`ScriptProbeService`, the same service in debug builds with a `probe` message) refused listing the app's files, reading a file the test had just written, the config and the key file (`ENOENT`: the data folder isn't there for it), writing, preferences, the keystore, a socket to a local port the test itself could reach, the internet and a name lookup (`EACCES`, "missing INTERNET permission"); a silent program's process gone 3.0 to 3.4 s after it was asked; with a long wait, the service ending itself after 5.0 to 5.1 s with "it computed for too long"; the 50 ms limit ending a loop with the service still answering; and all 15 starters dreamed end to end from the brain's Python through `Bridge` and the isolated service, with the same calls and words as the dream in the brain's own process.
- **The switch is on:** `LIVE_ON_PHONE = True`, because every vector passes in Kotlin and the instrumented tests pass. The two tests that check the phone with the switch off now set it off themselves (`test_who_may_ask_for_a_program_and_the_switches`, `test_on_the_phone_with_the_switch_off_scripts_never_go_live`, renamed from `test_on_the_phone_scripts_never_go_live`). `tests/test_script_phone.py` (7) runs the `Phone` engine against the real PC host through a stand-in bridge: the same JSON lines, a silent process killed, a dead or missing bridge as a crash, a starter dreaming the same, the engine chosen on the phone, and a program going live on the phone with the switch's own value.
- **Known differences from the Python evaluator** that no vector shows: `sorted()` compares in a different order, so a list mixing things that can't be compared may fail at a different pair (the same crash and line); `x in range(...)` with a float answers at once where Python walks the range; a hand-made program with an unknown statement or target is refused at load rather than when reached. Crash texts are the same words, but Kotlin's exception names appear where Python's would ("something went wrong (...)").
- **Not done:** nothing on the Pixel 6 Pro (the evaluator's speed on its cores, a process start on it, a living Pebble's programs); `connectedDebugAndroidTest` is not used, because it uninstalls the app afterwards (`android/README.md` says how to run the instrumented tests).

**Deviations from the plan, and why:**
- Item assignment (`d[key] = value`), unpacking (`a, b = pair`), `is None`, constant argument defaults, type hints on arguments and docstrings are allowed: counting needs `d[k] += 1`, E4B writes the others constantly, and none reaches anything new. Everything else follows the plan's lists; f-strings keep plain `{name}` fields only.
- `USES` names ability groups: `say` covers `say_to`, `look` covers `where`, `who_here`, `room` and `state`, and `keep`, `kept`, `now`, `today`, `feel`, `note`, `wait`, `chance`, `pick` and `finish` need no line, as the plan's own example (USES `["look", "say"]` with `say_to`, `keep` and `finish`) implies.
- Refusals of questions return an empty answer, not "refused: ...", so `for x in look()` can't walk the letters of a refusal. Refusals that are wrongdoing are counted toward the three; "not now" ones (quiet hours, asleep, a low battery, an unknown room, no eyes, busy) are not.
- `chance()` and `pick()` are answered by the brain from its chaos stream (a new lever, `scripts`), so the evaluator has no randomness of its own and the vectors replay exactly.
- `chirp()` and `hum()` are in the table but refused: this body has neither, as the try card already says.
- One process per running program, not one for all, so a hung or crashing program never takes another's values or time with it; at most three.
- People's names reach a program in small letters ("sam"), the same as `FOR`: E4B compared `who == "sam"` and got "Sam".
- The dream lays watched events only in waking hours (the household's quiet hours), dreams a week for Pebble's own programs, and counts up to the moment of the report.
- Going live always dreams a version that hasn't been dreamed, whoever wrote it, and a new version that fails its dream or crashes on its trial goes back to the last good one.
- A person's `do()` waits behind someone else's live request for up to 15 minutes, as their items for later do; Pebble's own programs are refused at once.
- The frozen part of the writing prompt is 1,159 tokens (the language card 359, the ability table 472, the shape of a script 256, the guide 68), so with the laws it is 85 over its 1,200 row: the plan's 400 and 500 left out the shape, and a shorter card lost the events' meanings.
- New files beyond the plan's list: `live.py` (Life's side: the abilities, the manager, the switches), `voice.py`, `scene.py`, `eval.py`, `make_vectors.py`.
- Voice words for programs are read by plain code in `Commands._consider`, before the try loop and the agenda, rather than in `conversation/`, the same door as the other plain-code readers.

- **The format (piece 2, `understand/request.py`, `grammar.py`):** `then` up to 8, `repeat` 1 to 10, `metres` up to 30 (the gap on `follow`), `until` back/called/seconds/asked/told or an event, seven more change words, `when` (every field of piece 3's table), `on` (piece 4's events, `first_of`), the logic tree of piece 4b (`if`/`then`/`else`, `unless`, `while`, `all`/`any`/`not`, named checks and their `result`; at most 3 deep, 12 steps, 8 in a row, 4 condition parts, refused past that), `cannot_tell` for what Pebble can't sense, and the new kinds `say_to`, `set_rule`, `end_rule`, `list_rules`, `check`, `watch`, `again`, `try_new`, `list_later`, `cancel_later` and `change_later`. Field names are kept and `from_dict` still clamps. The grammar takes fields in any order and holds the nesting limits.
- **What runs now:** the old kinds as before, plus `repeat`, chains of up to 8 and the `until` words told/asked. Every step is gated when it starts with the asker's trust as it is then (`Commands.fresh`); before, a plan kept the trust from when it was asked, and a plan of three or more steps silently lost its tail (fixed). Everything that needs pieces 3 to 13 gets an honest line ("I can't do reminders yet.", "I can't wait for something to happen first yet.", "I don't know how to do that yet.") and a `not_yet` record with the parts, never the words; the gate refuses the same. `for_mind`, `ack`, `resolve` and `start_activity` (now with `repeat` and `metres`) take the new format.
- **The front door (piece 1, `understand/understanding.py`, `understand/cover.py`):** instant in code: stops, harm, the listening words, answers to Pebble's question, and talk not meant for Pebble; the rules win when sure and every meaningful word was used (the word-coverage check); otherwise E4B reads, with no motion-word gate in `model_leads`; Pebble starts the rules' first step at once and E4B's reading finishes the chain or swaps the step through the gate; after 3 s (the life's clock) the rules stand and Pebble says "I'm not sure I got all of that." when words were left over; the house and household readers ask the same door before taking a line; the request prompt is read ahead on partial words beside the reply's; `Commands.request_words` takes plain words from code. `GUIDE` is rewritten (31 examples as earlier turns, 25 since the E4B pass below), `MAX_TOKENS` 160 (the longest expected reading is 72 tokens). Plain code tidies the model's reading (the speaker's name becomes "me", animals become things, a keep-out rule about a thing is talk).
- **The dial `reading.mode`** (registry, `CHOICE` kind; Pebble or the owner) stays **`rules_first`**; a warm or hot phone falls back to it by itself.
- **The measuring stick (piece 0):** `understand/eval_flex.jsonl`, 197 lines (all 30 sentences from 21 October, 47 of logic, 14 that stay talk, 14 never a command), `--set flex`, a scorer that treats the same meaning as the same (README).

- **Fixed in code (no prompt tokens), `understand/resolve.py` `tidy` on every reading:** thing words as the rules say them (mug is cup, telly is tv, "Dad's hat" has Dad as owner), Pebble's own name on come/follow/look means the speaker, come or go to a "place" that is a thing or a person, look at a "place" that is a thing; and talk for readings Pebble can't act on (where is the beach, a message to Pebble itself, a teach that names a person). **Model only, `Understanding.from_model`:** chasing something alive is harm; a toy chased or kicked is play; a known lifeless thing is a request it can't do, while people, "it" and unknown words stay harm; a command on a saying ("look at the time"), a sound or smell, a vague "later", or a message that only repeats the line is talk. ## Navigation (`brain/pebble/nav/`), fixed 19 October 2026
Follow, come, go to, find, rooms, docking legs and "go back" all go through `kit.nav`.
- Follow keeps the asked gap by straight-line distance as well as along the trail (scene minimum 0.82 m for 0.8 m asked).
- Animals: Pebble stops within 0.3 s of seeing one inside its gap and backs off up to 20 cm over floor it knows is clear, on every motion path. An animal that walks in from outside the 70° camera view can still get closer than 0.8 m (scene: about 0.38 m, was 0.19 m). That needs side sensing, not software.
- Come and go-to-thing hand nav a goal, so Pebble plans round cables and floor clutter instead of stopping and spinning. Pointed spots that are in or behind something are approached as close as possible.
- The alive layer only nudges the pose from landmarks when the pose is less sure than the landmark guess; before, it pushed a good pose up to 1 m off.
- Stability: the stairs test spun without yielding to the sim clock, used 36 GB and broke later tests. Fixed; suite runs are repeatable.
- The stuck-and-free loop is fixed (recovery counts only after real movement; a chase ends after a minute out of sight). Turning on the spot beside furniture, a bump at a wall's end read as glass, and the sim's carried-gravity frame are fixed too.
- Sim trial over 20 seeds (office, today's motors; `python -m pebble.nav.sim.trial --modes after --seeds N`): the old follow covered 0 % of the route. Now a walker who waits when called is followed to the end in 15 of 20 runs (45 % of the route on average), one who slows in 15 of 20 (81 %); a brisk walker (four times Pebble's speed) is lost at the first corner.
- Tests now cover anticipation round a corner, short cuts and keeping the map while carried. README section "Getting around and following".

## Speed pass, first part (19 October 2026)
`reports/Making Pebble quicker to respond.md` has the evidence and the ranked fixes. Built:
- **Thinking off:** Gemma 4's hidden thinking was on by default in the pinned llama.cpp and could use up a reply's whole budget. `--reasoning off` and `chat_template_kwargs` now turn it off.
- **A window of 8,192** with compaction fitted to the server's real window (read from `/props`) and room for the tool list, which alone was close to the old 4,096 limit.

## Speed pass, second part, and thinking out loud (19–20 October 2026)
From `reports/Cutting response time drastically.md` (owner's answers at its top) and `plans/thinking-out-loud.md`. Brain side built; each prompt change has its own switch in `profiles/model_gemma4_e4b.json`:
- **Background thinking gives way:** every mind call is either "a person is waiting" or "background". A background call is cut off at once when someone starts talking to Pebble (llama-server cancels on the closed connection), its events go back, and it runs later. No turn runs until 30 s of quiet.
- **The reply shares the turn's system text and tools,** with who is here now, the reply guide and the recent talk in the message and the person's words last. The household is listed in the system text, so an arrival no longer forces a re-read.
- **Reading ahead:** the next reply's start is read again in idle time whenever it changes, and addressed speech is read in on partials while the person talks. In a fake one-slot server test, 5 tokens were left to read after the person stopped, against 173 without. Only speech that looks addressed to Pebble; nothing is stored.
- **Ready-made social lines** (hello, how are you, thanks, good night, bye, praise) with no model call; Pebble writes a few of its own when idle (`social.json`).
- **A steady tool list** (all tools in a fixed order; the ones it can't use right now are named and refused by the gate), and the `say` tool spoken sentence by sentence while the wordsmith writes.
- **Holds while it thinks:** a glance and head tilt at 0.3 s, a first hold at 0.6 s (1.0 s once answers usually come within 1.2 s), an echo of short questions, a second hold at 2.5 s, "Still thinking" at 6 s, the slow line at 15 s; at most three. A small-model hold is asked for when the first is spoken.
- **Pebble learns its own holds** (`holds.json`): a Thompson-sampling bandit per situation and stage, per person for known people; stock holds keep a floor; its own holds are on trial first; "stop saying …" drops one for that person; "why do you say …?" is answered; forget deletes a person's weights.
- **Not checked:** reply and tool-use quality with the reordered prompts. The evals don't build model prompts, so judging it needs Gemma 4 on the PC: about a 5 GB download, which needs the owner's OK.
- **Android side** (the Android agent, after round 3): a small prompt batch (`-b`/`-ub` 64–128) so a give-way is quick, the drafter, the end-of-turn model, self-measuring, heat. Then Q4_0 against Q4_K_M, a Q8_0 projector, self-measured threads. "Measure the eyes again" should also call `LlamaChoice.forget()`.

## Fortifying Pebble (20–21 October 2026), built; sim, PC and emulator only
From `reports/Fortifying Pebble.md` (owner's answers at the top). Tests: firmware 96 native (ESP32 build clean), Kotlin 202, brain 1,999 green; the firmware, brain and app check the same handshake vectors.
- **The body:** Bluetooth is off unless the bumper is held 3 s with the wheels still (a 2-minute pairing window; the phone nods to confirm). Settings (`C`), reboot (`R`) and the new link key (`K`) go over USB only, with tighter bounds (edge 40–150 mm, stop 30–300 mm, cpm 0 or 5–60, tilt inside −35..90, trim ±10) and at most 4 writes a second. Wi-Fi and Bluetooth links need a shared-key HMAC handshake, then counter-tagged lines both ways (no replays); an unproven link may only stop and ping, and anyone may still stop Pebble. Reversing is capped at power 450 and limited to floor just driven forward over (no rear drop sensor); otherwise a reverse becomes a turn (status flag 128). The brain reads the body's settings at every link-up and won't drive an unsafe body.
- **The phone:** the link key lives in the Android keystore (StrongBox first), paired over the USB cable from the admin screen. Models are pinned by SHA-256 and size (`ModelAllow.kt`) and kept in internal storage (the old folder is a drop folder; unknown files are named, not loaded); the app's GGUF reader is bounds-checked. The Wi-Fi receiver binds to the Wi-Fi address only, takes its code in a header, accepts one file, and a sent profile keeps only camera angles, cpm and wheel track. adb is blocked once the PIN is set (a 30-minute allow on the admin screen); the kiosk pause re-locks itself; the admin screen closes after 2 minutes idle; new device-owner restrictions; USB data off while the body is on Wi-Fi where allowed; version rollback refused.
- **The brain:** a heard line is "sure" only with a confident voice match plus a face in view moving its lips (once face prints exist, that face seen), or the family word. A voice alone does everyday things; following, guarded things, house actions and alarm stand-downs need a sure line. A claimed name counts for "come here" only. Tool calls take their asker from who actually spoke that turn; trust changes, forgetting and introductions follow only a live, sure request. Alarm stand-downs need a sure, addressed line plus a confirmation ("Is it really fine?"); a fall or call for help ends only for the person who fell or a trusted person in view; ongoing beeping is raised again after 30 s, nothing is quietened for an hour. Children and friends are never told where medicines, knives, lighters, matches or chemicals are; keys and valuables need family or trusted. The inner circle comes from the owner only. A guest's mute lasts at most 2 h and ends 10 min after they leave; "help" is spotted with the ears off. A profile can't switch safety off or run unknown commands. One saved password try limit on every owner-password path; passwords need 12 characters; card showings are noted. "Forget" matches whole words, at most 5 memories. Logs keep events, not words. ## House rules for whoever continues
- No comments or docstrings in code. Plain words in docs.
- No personal data, absolute user paths, keys or a Pebble "self" in the repo. The project is meant to be publishable.
- Fetched models stay git-ignored; only models made here are tracked (`hazards.onnx`, `prints.onnx`, `objects.onnx`, `yamnet.onnx`). Check any staged file over 5 MB before committing.
- Brain tests: `cd brain && .venv/Scripts/python -m pytest -q` (the summary line is hidden by config; count dots and failures). Fetch models first: `python -m pebble.eyes.fetch` and `python -m pebble.speech.fetch`.
- The laws (`brain/pebble/laws.py`) come first; all motion goes through permissions, the motion guard and stop handling.
